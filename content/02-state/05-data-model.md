# 软件怎么把“人和文章”记成数据？

你认识一篇文章，会记得标题、内容、作者；你认识一个收藏，会知道谁收藏了哪篇文章。电脑要处理这些东西，也需要明确保存哪些信息、怎样区分它们。

**数据模型，就是软件选择用哪些记录和关系，来表示它关心的世界**。它像一套有明确栏目和连接方式的登记簿。

## 同叫《旅行》，不代表是同一篇

假设阅读助手里有两篇文章都叫《旅行》。只用标题识别文章，收藏和删除时就可能混淆。

程序可以为每篇文章分配不重复的编号，例如 A17 和 A28。这个用来辨认具体对象的值，叫**标识**，常见名字是 ID。你看到标题，程序用编号确认到底是哪一篇。

需要独立辨认的对象，比如用户、文章、收藏记录，常叫**实体**。实体可以有多个信息项，程序员会叫它们字段：文章的编号、标题、正文就是不同字段。

## 单个记录之外，还需要关系

“小林收藏了 A17”连接了用户和文章。文章本身不必复制一份到每个人名下，可以另外保留“用户是谁、文章是谁”的收藏记录。

这样两个人收藏同一篇文章，能表示为两条关系；文章只有一份正文。到底共用正文还是各自保留快照，取决于产品希望文章更新后收藏者看到什么。

## 软件能做什么，取决于记住了什么区别

如果只保存“这篇被收藏过”，却没保存是谁收藏，就无法准确生成每个人自己的收藏夹。如果希望区分草稿和已发布文章，就要留下这个区别，并规定它怎样改变。

这些要求还可以形成**约束**，也就是记录必须符合的规则：编号不能重复、收藏对应的文章必须存在。例如数据库可以帮助检查某些约束，但仍需要人先明确规则。

## 数据模型和数据库是什么关系？

数据模型描述“我们需要表达什么”。数据库是帮助保存和管理这些信息的软件。模型也可以被写进文件，数据库里也可能放着设计不清的记录。

先把对象、信息项和关系想清楚，存储工具才知道要保存什么。信息接下来怎样变化，交给[状态](06-state.md)解释；怎样保存与查找，交给[存储](07-storage.md)。
